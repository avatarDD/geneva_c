# geneva_c — пошаговый план портирования Geneva на C

Цель: переписать [Geneva](https://github.com/Kkevsterrr/geneva) (исполнитель
стратегий `engine.py` и генетический подборщик `evolve.py` + `evaluator.py`)
на C так, чтобы один и тот же код работал на слабых роутерах любых архитектур
(OpenWrt, Keenetic/Entware: mips, mipsel, arm, aarch64 …) и на ПК с Linux и
Windows, и чтобы его было легко встроить в zapret-gui и Zapret2_AutoTuner.

---

## 1. Что такое Geneva (кратко)

- **Стратегия** — два леса деревьев действий: исходящий и входящий,
  разделённые `\/`. Пример:
  `[TCP:flags:PA]-duplicate(tamper{TCP:dataofs:replace:10}(tamper{TCP:chksum:corrupt},),)-| \/`
- **Дерево** = триггер `[протокол:поле:значение(:gas)]` + дерево действий.
- **Действия:** `tamper` (replace/corrupt/add/compress), `duplicate`,
  `fragment` (TCP-сегментация или IP-фрагментация, порядок, overlap), `drop`,
  `sleep`, `trace`.
- **Исполнитель** ловит пакеты через NFQUEUE (iptables) и прогоняет их через
  стратегию; Python + scapy + netfilterqueue.
- **Подборщик** — генетический алгоритм (мутация, скрещивание, турнирный
  отбор, элита, зал славы), фитнес считает evaluator: запускает
  плагин-клиент (http, dns, sni, smtp, echo…) с движком и штрафует за
  сложность, неиспользуемые деревья и лишние пакеты.

## 2. Ключевые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Язык и стандарт | C11, без внешних библиотек | статическая сборка под любую архитектуру, мало памяти |
| Зависимости | **ноль** runtime-зависимостей на Linux: свой NFQUEUE поверх netlink (без libnetfilter_queue/libmnl), свой pcap, свой JSON. На Windows только WinDivert (грузится динамически) | ставится одной копией бинарника на OpenWrt, Keenetic, Entware |
| Бинарники | **один** multi-call бинарник `geneva` с подкомандами | проще ставить и обновлять, общий код не дублируется; ~200–400 КБ static |
| Сборка | простой `Makefile` (`CC=…` для кросса) + zig cc в CI для всех архитектур | собирается и в OpenWrt SDK, и «руками» |
| Совместимость | формат стратегий байт-в-байт как у Geneva (разбор → печать даёт ту же строку) | библиотека стратегий Geneva и статьи работают как есть |
| Потоки | исполнитель — однопоточный event loop (poll + таймеры), подборщик — потоки-воркеры | Geneva создаёт поток на каждый `sleep`; на роутере это дорого |
| Память | без записи pcap на flash по умолчанию, образцы пакетов в RAM с лимитом | ресурс flash роутера |

Подкоманды:

```
geneva run       исполнитель стратегии (NFQUEUE / WinDivert)
geneva evolve    генетический подбор стратегий
geneva eval      проверка заданных стратегий (eval-only), N прогонов
geneva apply     прогон стратегии по pcap-файлу офлайн (отладка, тесты)
geneva check     разбор/проверка стратегии, красивый вывод дерева, JSON
geneva library   встроенная библиотека известных стратегий Geneva
geneva fw        печать/применение/снятие правил iptables/nftables
geneva ctl       клиент управляющего сокета (status, set-strategy, stop…)
geneva censor    симулятор цензоров Geneva 1–11 (для тестов и стенда)
geneva version   версия и возможности сборки (--json)
```

## 3. Интерфейс управления и телеметрия (под zapret-gui и AutoTuner)

1. **События — JSON Lines** (`--events=-|файл|none`): одна строка = один
   объект `{"ts":…, "ev":"…", …}`. Типы: `start`, `ready`, `strategy`,
   `stats` (периодически), `tree_fired`, `pkt` (только в trace-режиме),
   `warn`, `error`, `censorship` (замечен RST/инъекция), `generation`,
   `individual`, `best`, `hall`, `eval_request`, `exit`. Схема описывается в
   `docs/PROTOCOL.md` и версионируется полем `"proto":1`.
2. **Управляющий сокет** (`--control=unix:/var/run/geneva.sock` или
   `tcp:127.0.0.1:PORT` + `--control-token`): построчный JSON-RPC
   (`{"id":1,"cmd":"status"}` → `{"id":1,"ok":true,…}`). Команды: `status`,
   `stats`, `set_strategy`, `pause`, `resume`, `reload`, `log_level`,
   `subscribe` (поток событий), `stop`; для подборщика ещё `hall`,
   `best`, `fitness` (ответ на `eval_request`).
3. **Внешняя оценка фитнеса** (`evolve --probe external`): подборщик
   присылает `eval_request` со стратегией, а контроллер (AutoTuner с
   настоящим браузером) отвечает `fitness`. Так AutoTuner использует свой
   критерий «полная загрузка», а GA остаётся в geneva.
4. **Логи** — текст в stderr по уровням `error…trace`, либо
   `--log-format=json` (тот же поток событий). На flash ничего не пишется,
   если не указан файл.
5. **Сигналы** (POSIX): SIGHUP — перечитать стратегию из файла, SIGUSR1 —
   сбросить статистику в события, SIGINT/SIGTERM — корректный выход со
   снятием правил firewall.
6. **Коды возврата** фиксированы и документированы (0 ок, 2 ошибка аргументов,
   3 ошибка стратегии, 4 нет прав/драйвера, 5 ошибка firewall …).

## 4. Улучшения относительно Geneva

- IPv6 (разбор, tamper, сегментация, фрагментация через Fragment header).
- Один NFQUEUE на оба направления (направление по hook), или два, как в Geneva.
- Изменённый пакет возвращается вердиктом, а не «drop + переотправка», если
  стратегия дала ровно один пакет: меньше нагрузки и нет проблем с conntrack.
- Отложенные вердикты и таймеры вместо `time.sleep` и потоков.
- Пометка своих пакетов `SO_MARK` + правила NOTRACK, чтобы IP-фрагменты не
  собирал conntrack; nft-цепочка после NAT (`postnat`), как в zapret2.
- Параллельная оценка особей без docker: каждый воркер со своим локальным
  портом, движок привязывает поток к особи.
- Обязательный baseline (canary): если ресурс без стратегии и так открывается,
  подбор не запускается (как правило AutoTuner).
- Учёт «остаточной цензуры» (GFW блокирует ip:port ~90 c): пауза и ротация
  целей.
- Детерминированный RNG (`--rng-seed`) — воспроизводимые прогоны.
- Офлайн-режим по pcap и дифференциальные тесты против Python-Geneva.
- Симулятор цензоров на C — e2e-тесты в network namespace прямо в CI.

## 5. Этапы

Каждый этап: код → тесты → **код-ревью** → исправления → коммит.

### Этап 0. Каркас
Структура репозитория, `Makefile`, слой платформы (POSIX/Win32: время,
сокеты, потоки, RNG), логгер, JSON-писатель/парсер, разбор CLI и диспетчер
подкоманд, мини-фреймворк юнит-тестов, CI-сборка gcc/clang/mingw.
*Готово, когда* `geneva version --json` собирается под Linux и Windows, тесты
запускаются `make test`.

### Этап 1. Пакеты
Разбор и сборка IPv4/IPv6/TCP (+опции)/UDP/DNS/DNSQR, контрольные суммы,
доступ к полям по именам Geneva (`get/set/gen/parse`), строковое
представление, правила автопересчёта len/chksum/dataofs как у scapy.
*Готово, когда* golden-тесты (эталоны сняты scapy) проходят байт-в-байт.

### Этап 2. Язык стратегий
Триггеры (wildcard, positive gas, negative gas), действия tamper/duplicate/fragment/drop/
sleep/trace, деревья, леса, разбор и печать, `geneva check`, `geneva apply`
(pcap in → pcap out), свой pcap reader/writer.
*Готово, когда* все стратегии `library.py` и тестов Geneva разбираются и
печатаются без изменений, а результаты применения совпадают с Python-Geneva
(дифференциальный тест).

### Этап 3. Исполнитель на Linux
NFQUEUE через netlink (bind, copy packet, verdict, mark, отложенный
вердикт), raw-сокеты v4/v6 с `SO_MARK`, таймеры, направление, статистика,
`geneva fw` (iptables и nft, идемпотентно, снимаются при выходе),
client/server-side, несколько портов, NAT-режим forwarder из Geneva.
*Готово, когда* e2e-тест в netns показывает, что стратегия реально применяется
к трафику (tcpdump видит ожидаемые пакеты).

### Этап 4. Телеметрия и управление
События JSONL, управляющий сокет, команды, подписка, сигналы, коды возврата,
`geneva ctl`, `docs/PROTOCOL.md`.
*Готово, когда* смена стратегии и статистика работают через сокет на живом
движке (тест).

### Этап 5. Исполнитель на Windows
WinDivert через `LoadLibrary` (без SDK при сборке), фильтр по портам,
перехват/инъекция в обе стороны, таймеры, тот же контроль/телеметрия.
*Готово, когда* собирается mingw/zig, smoke-тест на windows-runner в CI.

### Этап 6. Генетический алгоритм
Мутации деревьев/триггеров/действий, скрещивание, турнир, элита, зал славы,
ограничения протоколов/полей/действий, fix-trigger, no-gas, seed,
load-from, файлы поколений, `--no-eval`.
*Готово, когда* GA работает с фиктивным оценщиком, юнит-тесты на мутации и
скрещивание (все результаты остаются корректными стратегиями).

**Сохранение и продолжение поиска.** После каждого поколения подборщик
атомарно (tmp + rename) пишет checkpoint: номер поколения, популяцию с
фитнесом, зал славы, кэш оценок, состояние RNG и хэш параметров запуска.
`evolve --resume FILE` продолжает с места остановки (после Ctrl+C, падения,
перезагрузки роутера); при несовпадении параметров — предупреждение и выбор
`--resume-force`. Путь задаётся явно, чтобы на роутере писать в `/opt` или
tmpfs, а не во flash.

**Локальная база стратегий** (`--db FILE`, без SQLite — один JSONL-файл,
дописываемый в конец и периодически уплотняемый): каноническая стратегия +
профиль цели (проба, хост/порт, сеть) → число прогонов и успехов, средний и
лучший фитнес, время последнего успеха. Подборщик пополняет базу результатами
оценок и засевает начальную популяцию лучшими известными стратегиями для той
же цели. Команда `geneva db list|top|show|export|import|prune`, экспорт в
формат для zapret-gui и AutoTuner, доступ через управляющий сокет.

### Этап 7. Оценщик и пробы
Встроенный движок для оценки, пробы `http`, `tls` (ClientHello с SNI →
ServerHello и данные), `dns` (UDP/TCP, проверка подмены), `tcp` (свой
payload), `exec` (внешняя команда, например curl), `external` (оценка
контроллером). Фитнес и штрафы как в Geneva, canary/baseline, повторные
прогоны (min/avg/max), воркеры, пауза от остаточной цензуры, `geneva eval`.
*Готово, когда* `evolve` против локального цензора в netns находит рабочую
стратегию.

### Этап 8. Симулятор цензоров и e2e
Порт цензоров Geneva 1–11 (+ DNS-цензор) в `geneva censor`, стенд из трёх
namespace (клиент — цензор — сервер), e2e-тесты: известные стратегии
обходят нужных цензоров, подбор находит обход.

### Этап 9. Библиотека, server-side, упаковка, документация
Встроенная библиотека стратегий Geneva, server-side оценка с удалённым
`geneva agent`, init-скрипты (procd для OpenWrt, S-скрипт для Entware,
systemd), README (RU/EN), `docs/INTEGRATION.md` для zapret-gui и AutoTuner,
skill для агентов.

### Этап 10. Релиз
GitHub Actions: тесты + e2e, кросс-сборка zig (linux: x86_64, x86, aarch64,
armv7, armv6/5, mips, mipsel (soft-float), mips64, riscv64, ppc; windows:
x86_64, x86, arm64), архив Windows с WinDivert из официального релиза,
`SHA256SUMS`, публикация релиза по тегу.
