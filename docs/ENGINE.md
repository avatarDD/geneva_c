# Исполнитель (`geneva run`)

```
sudo geneva run -s STRATEGY -p PORTS [опции]
sudo geneva run -f strategy.txt -p 80,443 --events - --stats-interval 10
```

Ядро движка общее (стратегия, sleep, события, управление), пакеты дают
бэкенды: NFQUEUE на Linux и WinDivert на Windows (раздел «Windows» ниже).

На Linux нужны root (или CAP_NET_ADMIN + CAP_NET_RAW), модули
`nfnetlink_queue` и `xt_NFQUEUE` (iptables) или `nft_queue` (nftables).
Внешних библиотек нет.

## Как идут пакеты

1. Правила firewall отправляют в NFQUEUE (по умолчанию очередь 310) пакеты
   на порты сервиса (`-p`) и ответы с них. Направление: хуки PREROUTING и
   INPUT дают «in», OUTPUT и POSTROUTING — «out», в FORWARD оно
   определяется по портам.
2. Пакет проходит стратегию. Результат возвращается так:
   - первый пакет без задержки уходит **вердиктом** NFQUEUE с новыми байтами.
     Ядро не трогает их, поэтому сохраняются испорченные `IP:chksum`,
     `IP:len` и нулевой `IP:id`;
   - остальные пакеты отправляются через raw-сокеты с меткой `--mark`
     (по умолчанию `0x20000000`). Правила пропускают такие пакеты, а
     conntrack их не отслеживает (`--no-notrack` отключает это). Для IPv4
     сокет ставит `IP_NODEFRAG`, чтобы наши IP-фрагменты не собирались
     обратно;
   - пакеты с `sleep` ждут в таймерах. Если задержаны все, исходный пакет
     удерживается в очереди и получает вердикт позже (отложенный вердикт),
     а не переотправляется;
   - входящие пакеты, как в Geneva, дают не больше одного результата и не
     задерживаются.
3. Ограничение raw-отправки: Linux сам заполняет длину и контрольную сумму
   IPv4-заголовка у raw-пакетов. Поэтому порча этих полей сохраняется только
   у пакета, который уходит вердиктом.

Исполнитель однопоточный: poll по сокету netlink, таймеры и сигналы.

## Правила firewall

`--firewall auto` (по умолчанию) сначала пробует nftables (таблица
`inet geneva_<очередь>`), а при ошибке переходит на iptables (цепочки
`GENEVA_<очередь>_OUT/IN/NT` в mangle и raw, а также ip6tables). Правила
ставятся при старте и снимаются при выходе по SIGINT/SIGTERM. Повторная
установка идемпотентна. Если процесс был убит, правила с `--queue-bypass`
не блокируют трафик, а `geneva fw down -p ...` их убирает.

| Опция | Смысл |
|---|---|
| `-p 80,443,8000-8100` | порты сервиса |
| `--server-side` | работа на сервере: исходящие идут с этих портов |
| `--proto tcp,udp` | протоколы (по умолчанию tcp) |
| `-i wan` | только трафик через этот интерфейс (роутер) |
| `--first N` | только первые N пакетов соединения (экономия CPU на роутере) |
| `--dir out` | перехватывать одно направление |
| `-4` / `-6` | только IPv4 / только IPv6 |
| `--prenat` | nft: исходящие до SNAT (по умолчанию после, приоритет 101) |
| `--forward-to ADDR` | режим forwarder из Geneva: DNAT портов на ADDR и masquerade |
| `--firewall none` | правила ставит кто-то другой (`geneva fw print` их покажет) |

`geneva fw print|up|down` с теми же опциями печатает, ставит или снимает
правила вручную.

## Телеметрия

`--events -|stderr|FILE` включает поток событий JSON Lines:

- `start`: версия, pid, очередь, порты;
- `strategy`: стратегия (при старте и после SIGHUP);
- `ready`: правила стоят, движок принимает пакеты;
- `stats`: периодически (`--stats-interval`, по умолчанию 10 с), по SIGUSR1
  и при выходе. Содержит счётчики `pkts_out`, `pkts_in`, `triggered`,
  `accepted`, `modified`, `dropped`, `injected`, `delayed`, `pending`,
  ошибки, а также срабатывания каждого дерева в `out_trees`/`in_trees`;
- `error`: ошибка (стратегия, очередь, firewall, перезагрузка стратегии);
- `exit`: код возврата и причина.

`-v` / `--log-level trace` пишет в лог каждый пакет и результат стратегии.
`--pcap FILE` сохраняет выпущенные движком пакеты (на роутере пишите в tmpfs).

Сигналы: SIGHUP перечитывает `--strategy-file` (если новая стратегия не
разбирается, остаётся старая), SIGUSR1 отправляет `stats`, SIGINT/SIGTERM
снимают правила и завершают работу.

Коды возврата: 0 — ок, 2 — аргументы, 3 — стратегия, 4 — нет прав или
модулей ядра, 5 — firewall, 6 — ввод-вывод.

## Управление

`--control unix:/var/run/geneva.sock` (или `tcp:PORT`, с
`--control-token` для доступа не только с localhost) открывает управляющий
сокет: статус, статистика, смена стратегии на лету, пауза, уровень лога,
подписка на события, остановка. Клиент — `geneva ctl`. Формат событий и
команд — `docs/PROTOCOL.md`.

## Windows

```
geneva.exe run -s STRATEGY -p 80,443 -c tcp:47123 -e events.jsonl
geneva.exe fw print -p 80,443        # показать фильтр WinDivert
```

- Нужны права администратора и WinDivert 2.x из официального релиза автора
  (https://github.com/basil00/WinDivert/releases): `WinDivert.dll` и
  `WinDivert64.sys` (`WinDivert32.sys` для 32-битной Windows) кладутся рядом
  с `geneva.exe`. DLL грузится только из каталога `geneva.exe`, не из текущего
  каталога и не из PATH; для сборки SDK WinDivert не нужен.
- Правил firewall нет: перехват задаёт фильтр WinDivert, построенный из тех же
  опций (`-p`, `--proto`, `--server-side`, `--dir`, `-4`/`-6`). Петлевой
  трафик не перехватывается. `--iface` принимает индекс интерфейса
  (`netsh interface ipv4 show interfaces`). Linux-опции `--first`,
  `--forward-to`, `--prenat` и `--firewall` на Windows отклоняются.
- Пакеты принимает отдельный поток; результаты уходят через `WinDivertSend`
  с адресом исходного пакета, то есть в ту же сторону и через тот же
  интерфейс. Наши байты отправляются как есть (флаги контрольных сумм
  выставлены), поэтому специально испорченные суммы доходят до сети.
  Пакетам с незавершёнными из-за offload суммами они пересчитываются при
  приёме.
- `--queue-maxlen` задаёт длину очереди WinDivert (32–16384). `--queue` и
  `--mark` на Windows не используются. Ctrl+C и закрытие консоли
  останавливают движок; SIGHUP/SIGUSR1 нет — используйте команды `reload` и
  `stats` управляющего сокета (unix-сокетов на Windows нет, только `tcp:`).
- Windows может договариваться об ECN, и тогда её SYN несут флаги `SEC`, а не
  `S`: триггер `[TCP:flags:S]` из стратегий, найденных на Linux, на них не
  сработает. Добавьте дерево с `[TCP:flags:SEC]` или отключите ECN
  (`netsh int tcp set global ecncapability=disabled`).
- В событиях `start`/`ready` и в ответе `status` поле `backend` равно
  `windivert`, `firewall` — тоже `windivert`.

Проверка: `tests/windows/smoke.ps1` (в CI на windows-latest) запускает
движок с официальным WinDivert, проверяет HTTP через движок, дублирование
SYN, то, что drop действительно рвёт соединение, паузу, `stop` и работу сети
после выхода.

## Проверка

`tests/e2e/run.sh build/geneva` (root) поднимает два network namespace и
проверяет по захвату tcpdump на стороне сервера:
- дублирование с tamper (путь через вердикт и через raw);
- сегментацию TCP и фрагментацию IP (v4 и v6);
- порчу контрольной суммы IP;
- sleep, drop, входящий tamper и SIGHUP;
- снятие правил при выходе;
- управляющий сокет: смена стратегии, пауза, подписка, токен, stop.

`FIREWALLS="auto iptables nft"` выбирает проверяемые бэкенды firewall.
