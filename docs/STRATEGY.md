# Язык стратегий geneva_c

Синтаксис и семантика совпадают с Geneva (`actions/*.py`, `layers/*.py`):
стратегия, которую принимает Geneva, разбирается и печатается так же, а
применение к пакету даёт те же байты. Это проверяет `tools/geneva_diff.py`
в CI против Python-Geneva на закреплённом коммите.

## Синтаксис

```
strategy := out-forest "\/" in-forest
forest   := { tree }                      деревья через пробел
tree     := "[" trigger "]-" [action] "-|"
trigger  := proto ":" field ":" value [":" gas]
action   := name ["{" params "}"] ["(" [left] "," [right] ")"]
```

Пример: `[TCP:flags:PA]-duplicate(tamper{TCP:dataofs:replace:10}(tamper{TCP:chksum:corrupt},),)-| \/`

- Протоколы: `IP`, `TCP`, `UDP`, `DNS`, `DNSQR` (как в Geneva) и `IPv6`
  (расширение). Регистр не важен и сохраняется при печати. Поля `IP:ttl`,
  `IP:tos`, `IP:proto`, `IP:src/dst/load/version` работают и на IPv6
  (`hlim`, `tc`, `nh`).
- Значение — целое, если его принимает Python `int()` (`080` → `80`,
  `+1_000` → `1000`), иначе строка; `int` никогда не равно строке
  (`[TCP:flags:0]` не совпадает с пакетом без флагов — как в Geneva).
- `*` в конце значения — wildcard: подстрока (`[TCP:flags:A*]` ловит `A`,
  `PA`, `RA`, `SA`). Числовые поля сравниваются по десятичной записи.
- Gas: `N > 0` — сработать N раз; `0` — никогда; `N < 0` («бомба») —
  пропустить |N| совпадений, затем срабатывать всегда.
- Несколько `\/`: всё после первого — входящий лес. Кавычки по краям
  снимаются. Пробел внутри дерева — ошибка.

## Действия

| действие | параметры | ветвление | смысл |
|---|---|---|---|
| `tamper` | `{proto:field:replace:value}`, `{proto:field:add:N}`, `{proto:field:corrupt}`, `{DNS:qd:compress}` | левая | изменить поле; `corrupt` — случайное значение каждый раз |
| `duplicate` | — | обе | две копии |
| `fragment` | `{tcp\|ip:size:True\|False[:overlap]}` | обе | TCP-сегментация (размер в байтах) или IP-фрагментация (в 8-байтовых блоках); `-1` — пополам; `False` — обратный порядок |
| `drop` | — | терминальное | отбросить |
| `sleep` | `{seconds}` (по умолчанию 1) | левая | задержать отправку |
| `trace` | `{start_ttl:end_ttl}` (по умолчанию 1:64) | терминальное | один раз послать копии с TTL start…end-1 через 1 с |

Во входящем лесе допустимы только `tamper` и `drop`. Дерево без действий
(`[TCP:flags:A]-|`) поглощает пакет, на который сработало. Каждое
сработавшее дерево получает свежую копию исходного пакета, триггеры всегда
смотрят на исходный пакет.

## Отличия от Geneva

Строже там, где Geneva приняла бы стратегию и потом упала бы или сделала
что-то неожиданное:

- `tamper` без параметров (Geneva подставляет случайный) — ошибка;
- имена действий — только полные (`tamper`, не `tamp`); `duplicate{…}` и
  `drop{…}` — ошибка (Geneva падает с AttributeError);
- неизвестные поле/протокол/примитив в `tamper`, `add` с не-числом,
  `replace` без значения, отрицательный/нечисловой `sleep`,
  неверный `trace` — ошибка разбора, а не исключение во время работы;
- wildcard по числовому полю работает (в Geneva — TypeError);
- wildcard печатается со звёздочкой (Geneva теряла `*` при печати);
- печать gas — исходное значение, а не остаток;
- после `tamper` UDP-контрольная сумма пересчитывается (Geneva оставляет
  старую — её `Packet.set()` пересчитывает только IP и TCP, — и сервер
  отбрасывает такой пакет);
- TCP-сегментация пакета, у которого раньше изменили `IP:proto` или
  `IP:frag`, даёт нормальные сегменты (Geneva из-за повторного разбора
  scapy теряет данные и дублирует TCP-заголовок);
- IPv6: разбор, `tamper`, сегментация, фрагментация через Fragment header.

## Команды

```
geneva check STRATEGY...            канонический вид; код 3 при ошибке
geneva check -f strategies.txt      по строке на стратегию, # — комментарии
geneva check --pretty S             дерево, как Geneva pretty_print()
geneva check --json S               структура: триггеры, действия, параметры

geneva apply -s S -i in.pcap -o out.pcap -p 80     направление по порту сервера
geneva apply -s S -i in.pcapng -o - --dir in        все пакеты как входящие
geneva apply ... --rng-seed 1 --json -v             воспроизводимо, сводка, лог по пакетам
```

`apply` читает pcap (оба порядка байт, мкс/нс) и pcapng; Ethernet (с VLAN),
raw IP, Linux cooked v1/v2, BSD loopback. Пишет pcap с LINKTYPE_RAW и
наносекундными метками; задержка `sleep` прибавляется к метке времени.
Для входящих пакетов, как в движке Geneva, остаётся только первый
результат. Пакеты не на `--server-port` проходят без изменений.

## Проверка совместимости

```
python3 tools/extract_strategies.py /path/to/geneva > tests/geneva_strategies.h
python3 tools/geneva_diff.py --geneva /path/to/geneva --bin build/geneva
```

Первый скрипт только читает файлы Geneva и обновляет корпус для юнит-тестов
(`make test`). Второй импортирует Geneva (нужны `scapy==2.4.3`, `anytree`)
и сравнивает разбор, печать и результат применения каждой стратегии.
