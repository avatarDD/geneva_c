# Оценка стратегий: пробы и `geneva eval`

```
geneva eval --host blocked.example                         # базовая проба без стратегии
sudo geneva eval --host blocked.example -s '[TCP:flags:PA]-fragment{tcp:-1:True}-| \/'
sudo geneva eval --probe tls --host blocked.example -f strategies.txt --workers 4
sudo geneva evolve --probe http --host blocked.example --population 50 --workers 8
```

Оценщик — это `evaluator.py` Geneva без docker. Движок работает внутри
процесса. Каждый воркер подключается со своего блока локальных портов, и
движок применяет к пакетам этого блока стратегию воркера. Поэтому несколько
стратегий можно оценивать одновременно, а чужой трафик машины через движок
не идёт.

Пробе нужен заблокированный ресурс. Перед поиском `geneva evolve` запускает
ту же пробу без стратегии (baseline). Если ресурс открывается и без неё,
искать нечего: evolve завершается с кодом 7 (`--no-baseline` отключает
проверку). Пакеты этого прогона становятся пакетами canary-фазы Geneva:
из них мутации берут значения триггеров и tamper (если не задан `--packets`;
`--no-canary` отключает).

## Пробы

Успех — полный обмен, а не рукопожатие.

| `--probe` | Что делает | Успех |
|---|---|---|
| `http` (по умолчанию) | `GET --path` с `Host: --host`, `Connection: close` | ответ HTTP целиком: по Content-Length, chunked или до закрытия |
| `tls` | ClientHello с SNI `--host` (TLS 1.2 и 1.3, `--tls-version`) | ServerHello и весь первый полёт сервера: зашифрованные записи (1.3) или ServerHelloDone (1.2) |
| `dns` | запрос A (`--dns-aaaa`: AAAA) имени `--host` к резолверу `--ip` (по умолчанию 8.8.8.8), UDP или `--dns-tcp` | первый ответ с адресом, не из `--dns-bad` и из `--dns-expect`, если он задан |
| `tcp` | шлёт `--payload` на `--ip`/`--host`:`--port` | ответ с `--valid-contains` и не меньше `--min-bytes`; без них — любые данные |
| `exec` | команда `--cmd` (через `sh -c` или `cmd /c`) | код возврата 0 |
| `external` | запрос контроллеру (см. ниже) | ответ контроллера |

Общие проверки: `--valid-contains TEXT` (ответ должен содержать TEXT, иначе
«broken»), `--injected-contains TEXT` (это страница блокировки или
подменённый ответ, «injected»), `--min-bytes N`. Тексты ищутся в первых
256 КБ ответа. `--max-bytes` (4 МБ) — сколько данных считать достаточным.
`--bad-word WORD` добавляет к пути `?q=WORD`, как в Geneva.

TLS-проба не проверяет сертификат и не завершает рукопожатие: для этого
нужна криптография, а зависимостей у geneva нет. Полную загрузку по HTTPS
проверяет `exec` с curl:

```
--probe exec --cmd "curl -s -o /dev/null --max-time 10 --local-port {lports} https://blocked.example/"
```

В команде подставляются `{lports}` (блок портов воркера, `30000-30063`),
`{lport}` (его первый порт), `{host}`, `{ip}`, `{port}`. Через движок идёт
только трафик с портов блока, поэтому команда должна подключаться с них:
у curl это `--local-port {lports}`. `--timeout` для exec — время всей
команды (по умолчанию 20 с). Команду, которая не уложилась, geneva убивает
вместе с дочерними процессами.

## Фитнес

Оценки — как у клиентских плагинов Geneva (их значения умножены на 4):

| Исход | Фитнес | Когда |
|---|---|---|
| `ok` | +400 | полный обмен |
| `reset` | −360 | RST, отказ в соединении, ICMP unreachable |
| `injected` | −360 | страница блокировки, подменённый DNS-ответ, NXDOMAIN |
| `connect_timeout` | −400 | соединение не установилось |
| `timeout` | −480 | соединение есть, ответа нет (стратегия, вероятно, сломала поток) |
| `broken` | −480 | ответ неполный или не тот |
| `failed` | −400 | команда exec завершилась с ошибкой, прочие ошибки |

Затем штрафы `punish_fitness` Geneva для стратегии:
- при успехе −1 за каждое действие (короче — лучше);
- −10 за каждое дерево, которое ни разу не сработало;
- при успехе −½ за каждый лишний пакет, который отправил движок.

`--runs N` прогоняет стратегию N раз, `--fitness-by avg|min|max`
объединяет результаты (по умолчанию среднее, как в Geneva). В evolve пустые
стратегии получают −1000 без прогона, как в Geneva.

## Параллельность и порты

`--workers N` (до 32) оценивает N стратегий одновременно. Воркер i
подключается с портов `--local-ports + 64·i` … `+ 63` (по умолчанию от
30000) и перебирает их по кругу, чтобы новое соединение не попало на порт
в TIME_WAIT. Порты ниже 32768 не пересекаются с эфемерными портами Linux и
Windows, поэтому чужие соединения в блок не попадают.

Правила firewall ставятся на эти порты (`--queue`, по умолчанию 301,
`--firewall`, `--mark` — как у `geneva run`) и снимаются при выходе. На
Windows WinDivert ловит те же порты.

`--residual-wait SEC` — пауза воркера после неудачного прогона. Она нужна
для цензоров, которые после срабатывания блокируют ещё какое-то время все
соединения к серверу (так делает, например, GFW): иначе следующая стратегия
получит чужую неудачу.

## Внешний контроллер (`--probe external`)

Соединение делает контроллер (например, zapret-gui или Zapret2_AutoTuner),
а geneva ставит стратегию в движок и ждёт результат. Нужен `--events`
(обычно `-`) и один воркер. Перед каждым прогоном geneva пишет событие

```
{"ts":...,"ev":"eval_request","id":7,"strategy":"[TCP:flags:PA]-drop-| \/","run":0,"lports":"30000-30063"}
```

и читает из stdin строку с ответом:

```
{"id":7,"ok":true}            или  {"id":7,"fitness":350,"detail":"page loaded"}
```

`ok` даёт +400 или −400, `fitness` задаёт оценку прямо (штрафы Geneva
применяются после). Строки с другим `id` пропускаются. Если stdin закрылся,
поиск останавливается.

## `geneva eval`

Печатает `фитнес<TAB>стратегия` для каждой стратегии (`-s`, `-f FILE` или
аргументы). Без стратегий делает baseline и печатает его фитнес; движок и
права администратора для этого не нужны (`--no-engine` — тоже только
пробы). Код возврата 0, если хоть одна стратегия (или baseline) прошла,
иначе 1. С `--events` пишутся события `eval`.
