# Подборщик (`geneva evolve`) и база стратегий (`geneva db`)

```
sudo geneva evolve --probe http --host blocked.example --population 50 --generations 20 --workers 8
sudo geneva evolve --probe tls --host blocked.example --checkpoint /opt/geneva/search.ckpt --db /opt/geneva/db.jsonl
sudo geneva evolve --probe tls --host blocked.example --checkpoint /opt/geneva/search.ckpt --resume --generations 100
geneva db --db /opt/geneva/db.jsonl top -n 5
```

Это генетический алгоритм Geneva (`evolve.py`). Популяция стратегий
проходит скрещивание и мутации, затем оценку, турнирный отбор и элиту, и так
`--generations` поколений. Каждую стратегию оценивает проба через движок:
опции `--probe`, `--host` и остальные, а также baseline и фитнес описаны в
`docs/EVAL.md`. Движку нужны права root (на Windows — администратора).

Режимы без сети:
- `--no-eval` — фитнес всегда 0, как в Geneva;
- `--mock-eval TEXT` — тестовый оценщик: стратегия «проходит», если её текст
  содержит TEXT, и чем она короче, тем выше фитнес. Он проверяет цикл GA,
  checkpoint и базу.

В stdout в конце печатаются лучшие стратегии зала славы, по одной строке:
средний фитнес, число оценок и стратегия (`--top N`, по умолчанию 5).

## Опции (имена как в Geneva)

| Опция | По умолчанию | Смысл |
|---|---|---|
| `--population`, `--generations` | 250, 50 | размер популяции, число поколений |
| `--elite-clones` | 3 | копий лучшей особи в следующем поколении |
| `--mutation-pb`, `--crossover-pb` | 0.99, 0.4 | вероятности мутации и скрещивания |
| `--allowed-retries` | 20 | сколько раз одна стратегия может появиться снова |
| `--no-reject-empty` | выкл. | не отбрасывать мутации без действий |
| `--in-trees`, `--out-trees` | 0, 1 | деревьев в новой стратегии (0 входящих — входящий лес не меняется) |
| `--in-actions`, `--out-actions` | 2, 2 | действий в новом дереве |
| `--fix-trigger T` | — | один триггер для всех деревьев, например `TCP:flags:PA` |
| `--seed S` | — | все особи начинаются со стратегии S (она же первая элита) |
| `--load-from FILE` | — | начальная популяция из файла поколения |
| `--protos`, `--fields`, `--disable-fields` | `TCP`, все, — | доступные протоколы и поля заголовков |
| `--disable-action` | `sleep,trace` | запрещённые действия; с `--ext` ещё `x` (все x-действия) или имена x-действий (ниже) |
| `--no-gas` | выкл. | триггеры без «газа» |
| `--packets PCAP` | — | настоящие пакеты, из которых берутся значения триггеров и tamper (как пакеты canary-фазы Geneva) |
| `--probe`, `--host`, `--ip`, `--port`, ... | `http` | проба и цель (`docs/EVAL.md`) |
| `--runs`, `--fitness-by` | 1, `avg` | прогонов на стратегию и как их объединять, как в Geneva |
| `--workers` | 1 | стратегий, которые оцениваются одновременно (до 32; с `--probe external` — с 1.2, `docs/EVAL.md`; с `--agent` — только 1) |
| `--residual-wait` | 0 | пауза после неудачи (остаточная цензура) |
| `--no-baseline`, `--no-canary` | выкл. | не проверять блокировку без стратегии; не брать значения из её пакетов |
| `-o DIR` | — | файлы `generationN.txt` и `hallN.txt`, как в Geneva |
| `--rng-seed N` | — | воспроизводимый запуск |

Логи — `--log-level`, `--log-file`, `--log-format`, события — `--events`
(см. ниже).

## Сохранение и продолжение поиска

С `--checkpoint FILE` перед каждым поколением подборщик сохраняет состояние:
номер поколения, популяцию с фитнесом, элиту, зал славы (все оценки всех
стратегий, он же кэш оценок) и состояние генератора случайных чисел. Запись
атомарная: временный файл, сброс на диск, переименование. Поэтому при сбое
питания на роутере остаётся либо старый, либо новый checkpoint.

Ctrl+C или SIGTERM останавливают поиск после текущего шага. Позже
`--resume` продолжает с начала прерванного поколения. При тех же опциях
продолжение даёт ровно тот же результат, что и непрерывный запуск (это
проверяется тестом). `--generations` при продолжении можно увеличить.
Если изменились опции, которые меняют пространство поиска (популяция,
деревья, протоколы, поля, действия, seed, цель), продолжение
отказывается; `--resume-force` продолжает всё равно.

Путь задаётся явно: на роутере его стоит держать в `/opt` (USB-диск) или
tmpfs, а не во встроенной flash. Файл растёт вместе с залом славы, порядок —
сотни килобайт на тысячи стратегий.

## База стратегий

`--db FILE` (или переменная `GENEVA_DB`) — один файл JSON Lines, без
SQLite. Каждая оценка дописывает строку в конец. При чтении строки одной пары
«стратегия + цель» складываются; `geneva db compact` и закрытие разросшегося
файла переписывают его по строке на пару (атомарно).

```
{"s":"[TCP:flags:S]-drop-| \/","t":"http:example.com","runs":3,"ok":2,"fit_sum":512.5,"fit_best":397,"first":1730000000000,"last":1730000500000,"last_ok":1730000400000}
```

- `s` — каноническая стратегия, `t` — профиль цели (`--target`, по
  умолчанию из пробы: `http:blocked.example:80`, `dns:name@8.8.8.8`), чтобы
  результаты для разных целей и цензоров не смешивались.
- `runs`, `ok` — оценки и успехи (фитнес > 0). `fit_sum`, `fit_best` —
  сумма и лучший фитнес.
- `first`, `last`, `last_ok` — время в мс от эпохи.

Подборщик записывает в базу каждую оценку и засевает начальную популяцию до
`--db-seed N` (по умолчанию 10) лучшими успешными стратегиями для той же
цели.

```
geneva db --db FILE list [--target T] [--json]
geneva db --db FILE top [-n 10] [--target T] [--json]
geneva db --db FILE show 'STRATEGY'
geneva db --db FILE export [OUT] [--format jsonl|txt] [--target T]
geneva db --db FILE import FILE...      # базы JSONL или списки стратегий
geneva db --db FILE prune [--min-runs N] [--failed] [--older-than DAYS]
geneva db --db FILE compact
```

Ранжирование: доля успехов, затем средний фитнес, затем число оценок.
`export --format txt` даёт список стратегий, по одной в строке, для
`--load-from` и для внешних программ. Как этим пользуются zapret-gui и
AutoTuner — `docs/INTEGRATION.md`.

## x-действия (с `--ext`)

С `--ext` подборщик работает и с x-действиями zapret2 (`docs/EXT.md`,
X5a), а не только скрещивает те, что пришли в начальной популяции:

- **Новые x-действия.** Новое действие дерева с той же частотой, что
  `tamper`, — x-действие. Подборщик делает все действия, которые меняют
  то, что видит цензор: `xfake`, `xsplit`, `xdisorder`, `xfakedsplit`,
  `xfakeddisorder`, `xtcpseg`, `xhostfake`, `xtlsrec`, `xoob`, `xdrip`,
  `xrst`, `xsyndata`, `xsynack`, `xwssize`, `xhttp`, `xtlsclone`, `xtag`,
  `xsend`, `xmod`, `xudplen`, `xdhtdn` и комбинаторы `xrepeat`, `xwhen`,
  `xstop`, `xcutoff`; во входящем лесу — `xwsize` (окно в SYN,ACK
  сервера). Не делает: `xlog` и `xpcap` (только пишут журнал и захват) и
  обфускаторы (`xwgobfs`, `xippxor`, `xudp2icmp`, `xsynhide`) — их должна
  снимать вторая сторона, иначе соединение не работает. Блоб `xtlsclone`
  называется `gclone`, метки `xtag` — `gtag` и `gtag_no`: другие действия
  иногда берут их в `blob=` и `payload=`.
- **На сервере** (`evolve --agent`, `docs/SERVER_SIDE.md`) стратегия стоит
  на сервере: исходящий лес — пакеты сервера. Там подборщик делает и
  `xsynacksplit` и `xwsize` (SYN,ACK сервера), но не клиентские `xhostfake`,
  `xsyndata`, `xsynack`, `xwssize`, `xhttp`, `xtlsclone`; payload берётся
  серверный (`tls_server_hello`, `http_reply`...). Во входящем лесу
  сервера x-действий нет.
- **Протокол дерева.** Триггер TCP — действия для TCP, UDP — для UDP
  (`xudplen`, `xdhtdn`, `xfake`, `xsend`...); у остальных триггеров
  (`IP:`, `FLOW:`, `L7:`) — для протоколов из `--protos`. В дереве только
  UDP не выбираются ключи заголовка TCP (`seq`, `ack`, `ts`, `md5`, флаги,
  `tsup`, `nopdel`).
- **Мутация параметров.** Мутация действия (ветвь `ActionTree.mutate`, как
  у `tamper` и `fragment`) у x-действия делает одно из: новое значение
  параметра (45%), ещё один параметр (25%), параметр меньше (15%), другое
  x-действие с тем же числом поддеревьев, с параметрами, которые оно
  принимает и которые значат у него то же (15%). Результат разбирается
  заново теми же проверками, что и стратегия от человека; что они не
  пропускают, выбирается снова. Ключи условия согласуются: `iff=cond_payload_str`
  получает `pattern`, `percent` бывает только при `cond_random`.
- **Ключи.** Выбирается каждый ключ, который принимает действие, кроме
  `ifout` и `fwmark` (настройка самого хоста) и `ipfrag_pos_icmp`,
  `ipfrag_pos` (пакеты, которых в деревьях нет). Действие с параметрами
  сверх 24 мутация оставляет как есть.
- **Значения** — те, что используют стратегии zapret2 и сетка blockcheck2:
  маркеры позиций (`1`, `2`, `-1`, `midsld`, `sniext+1`, списки до 4),
  `ttl=N`, `ttl=auto:-D:MIN-MAX`, `ip_ttl`, `ip6_ttl`, `ip_autottl`,
  `ip6_autottl`, `seq`/`ack`/`ts` со сдвигом, `md5` (с данными и без),
  `badsum`, флаги TCP, заголовки IPv6 (`ip6ext` и `ip6_*`, с данными и
  без), `repeats`, `ipid`, `ipfrag` (и `ipfrag2`), его позиции и
  `ipfrag_next`, `payload` (все типы zapret2 по протоколу, `known`, `all`,
  отрицание `~`), `seqovl` и его шаблон, `tlsmod` (`rnd`, `rndsni`,
  `dupsid`, `padencap`, `sni=`, `none`), `host`, `urp`, окно и масштаб,
  `forced_cutoff`, `pattern_offset`, `sni_*` у `xtlsclone`, `stop`/`clear`
  у `xrepeat`, `delay` (у `xsend` до 20 мс), условия комбинаторов
  (`cond_random`, `cond_payload_str`, `cond_true`, `cond_false`,
  `cond_tcp_has_ts`, `L7:payload`, `L7:proto`, `FLOW:` по всем счётчикам,
  `FLOW:state`, `FLOW:retrans`, `TCP:flags`). Блобы — встроенные и все из
  `--ext-blob`: для TCP — записи TLS и запросы HTTP, для UDP — остальные,
  а также короткие `0x...` из одного байта. Что всё это выпадает, проверяет
  тест `xgen_coverage` (`tests/test_xgen.c`).
- **Что ломает пакет** (TTL, `seq`, `ack`, `ts`, `md5`, `badsum`, флаги,
  заголовки IPv6) достаётся только действиям, которые шлют подделки
  (`xfake`, `xfakedsplit`, `xfakeddisorder`, `xhostfake`, `xrst`,
  `xsyndata`, `xsynack`): на настоящих данных оно бы сломало соединение.
  При смене вида на действие с настоящими данными такие параметры
  снимаются; написанные человеком подборщик оставляет как есть.
- `--disable-action x` возвращает прежнее поведение: x-действия только
  переходят между особями при скрещивании. `--disable-action xfake,xoob`
  запрещает делать эти действия (уже имеющиеся меняются); имена — в любом
  регистре.

Без `--ext` подборщик ведёт себя как Geneva.

## События

С `--events` подборщик пишет:
- `start` с `mode: "evolve"`, `population`, `generations`, `target`, `resume`;
- `baseline`: `blocked`, `fitness`, `outcome`, `detail` — проба без стратегии;
- `eval` после каждой оценки: `strategy`, `fitness`, `runs`, `outcome`, `detail`;
- `generation` после каждого поколения: `gen`, `unique`, `evaluated`,
  `avg_fitness`, `best_fitness`, `best`;
- `result` в конце: `stopped` и `best` — список `{strategy, avg_fitness, runs}`;
- `exit`: `code` и `reason` (`done`, `signal`, `not_blocked`, `error`).

## Отличия от Geneva

- Мутация (`ActionTree.mutate`) учитывает `--disable-action`. В Geneva
  отключённые действия могли вернуться через мутацию.
- С `--ext` подборщик делает и меняет x-действия (раздел выше); в Geneva
  их нет.
- `--no-reject-empty` работает как написано: по умолчанию пустые стратегии
  отбрасываются. В Geneva флаг был инвертирован.
- Смена типа tamper с `corrupt` на `replace` подбирает значение. Geneva
  писала `replace:None`.
- Значения, которые нельзя записать в стратегии (адреса IPv6 с `:`, строки
  с пробелами и разделителями), не выбираются. Каждая особь проверяется на
  то, что её текст разбирается обратно в ту же стратегию.
- В дереве не больше 64 действий. Мутация, которая 1000 раз подряд даёт
  отвергнутые стратегии, оставляет особь как есть (Geneva зацикливалась).
- Из Geneva сохранены: частоты действий, вероятности ветвей мутации,
  порядок «скрещивание, затем мутация», турнир из 10 особей, правила отказа
  по залу славы и выбор триггера из настоящих пакетов. Последовательность
  случайных чисел, конечно, другая.
