# Подборщик (`geneva evolve`) и база стратегий (`geneva db`)

```
geneva evolve --no-eval --population 50 --generations 5 -o run1
geneva evolve --mock-eval drop --checkpoint /opt/geneva/search.ckpt --db /opt/geneva/db.jsonl --target test
geneva evolve --mock-eval drop --checkpoint /opt/geneva/search.ckpt --resume --generations 100
geneva db --db /opt/geneva/db.jsonl top -n 5
```

Это генетический алгоритм Geneva (`evolve.py`). Популяция стратегий
проходит скрещивание и мутации, затем оценку, турнирный отбор и элиту, и так
`--generations` поколений. Оценка стратегий против настоящего цензора (пробы
http/tls/dns и т. д.) появится на этапе 7. Пока доступны два режима:
- `--no-eval` — фитнес всегда 0, как в Geneva;
- `--mock-eval TEXT` — тестовый оценщик: стратегия «проходит», если её текст
  содержит TEXT, и чем она короче, тем выше фитнес. Он проверяет цикл GA,
  checkpoint и базу без сети.

В stdout в конце печатаются лучшие стратегии зала славы, по одной строке:
средний фитнес, число оценок и стратегия (`--top N`, по умолчанию 5).

## Опции (имена как в Geneva)

| Опция | По умолчанию | Смысл |
|---|---|---|
| `--population`, `--generations` | 250, 50 | размер популяции, число поколений |
| `--elite-clones` | 3 | копий лучшей особи в следующем поколении |
| `--mutation-pb`, `--crossover-pb` | 0.99, 0.4 | вероятности мутации и скрещивания |
| `--allowed-retries` | 20 | сколько раз одна стратегия может появиться снова |
| `--no-reject-empty` | выкл. | не отбрасывать мутации без действий |
| `--in-trees`, `--out-trees` | 0, 1 | деревьев в новой стратегии (0 входящих — входящий лес не меняется) |
| `--in-actions`, `--out-actions` | 2, 2 | действий в новом дереве |
| `--fix-trigger T` | — | один триггер для всех деревьев, например `TCP:flags:PA` |
| `--seed S` | — | все особи начинаются со стратегии S (она же первая элита) |
| `--load-from FILE` | — | начальная популяция из файла поколения |
| `--protos`, `--fields`, `--disable-fields` | `TCP`, все, — | доступные протоколы и поля заголовков |
| `--disable-action` | `sleep,trace` | запрещённые действия |
| `--no-gas` | выкл. | триггеры без «газа» |
| `--packets PCAP` | — | настоящие пакеты, из которых берутся значения триггеров и tamper (как пакеты canary-фазы Geneva) |
| `-o DIR` | — | файлы `generationN.txt` и `hallN.txt`, как в Geneva |
| `--rng-seed N` | — | воспроизводимый запуск |

Логи — `--log-level`, `--log-file`, `--log-format`, события — `--events`
(см. ниже).

## Сохранение и продолжение поиска

С `--checkpoint FILE` перед каждым поколением подборщик сохраняет состояние:
номер поколения, популяцию с фитнесом, элиту, зал славы (все оценки всех
стратегий, он же кэш оценок) и состояние генератора случайных чисел. Запись
атомарная: временный файл, сброс на диск, переименование. Поэтому при сбое
питания на роутере остаётся либо старый, либо новый checkpoint.

Ctrl+C или SIGTERM останавливают поиск после текущего шага. Позже
`--resume` продолжает с начала прерванного поколения. При тех же опциях
продолжение даёт ровно тот же результат, что и непрерывный запуск (это
проверяется тестом). `--generations` при продолжении можно увеличить.
Если изменились опции, которые меняют пространство поиска (популяция,
деревья, протоколы, поля, действия, seed, цель), продолжение
отказывается; `--resume-force` продолжает всё равно.

Путь задаётся явно: на роутере его стоит держать в `/opt` (USB-диск) или
tmpfs, а не во встроенной flash. Файл растёт вместе с залом славы, порядок —
сотни килобайт на тысячи стратегий.

## База стратегий

`--db FILE` (или переменная `GENEVA_DB`) — один файл JSON Lines, без
SQLite. Каждая оценка дописывает строку в конец. При чтении строки одной пары
«стратегия + цель» складываются; `geneva db compact` и закрытие разросшегося
файла переписывают его по строке на пару (атомарно).

```
{"s":"[TCP:flags:S]-drop-| \/","t":"http:example.com","runs":3,"ok":2,"fit_sum":512.5,"fit_best":397,"first":1730000000000,"last":1730000500000,"last_ok":1730000400000}
```

- `s` — каноническая стратегия, `t` — профиль цели (`--target`: проба, хост,
  порт, сеть — чтобы результаты для разных цензоров не смешивались).
- `runs`, `ok` — оценки и успехи (фитнес > 0). `fit_sum`, `fit_best` —
  сумма и лучший фитнес.
- `first`, `last`, `last_ok` — время в мс от эпохи.

Подборщик записывает в базу каждую оценку и засевает начальную популяцию до
`--db-seed N` (по умолчанию 10) лучшими успешными стратегиями для той же
цели.

```
geneva db --db FILE list [--target T] [--json]
geneva db --db FILE top [-n 10] [--target T] [--json]
geneva db --db FILE show 'STRATEGY'
geneva db --db FILE export [OUT] [--format jsonl|txt] [--target T]
geneva db --db FILE import FILE...      # базы JSONL или списки стратегий
geneva db --db FILE prune [--min-runs N] [--failed] [--older-than DAYS]
geneva db --db FILE compact
```

Ранжирование: доля успехов, затем средний фитнес, затем число оценок.
`export --format txt` даёт список стратегий, по одной в строке, для
`--load-from` и для внешних программ. Форматы zapret-gui и AutoTuner
описываются на этапе 9 (`docs/INTEGRATION.md`).

## События

С `--events` подборщик пишет:
- `start` с `mode: "evolve"`, `population`, `generations`, `target`, `resume`;
- `generation` после каждого поколения: `gen`, `unique`, `evaluated`,
  `avg_fitness`, `best_fitness`, `best`;
- `result` в конце: `stopped` и `best` — список `{strategy, avg_fitness, runs}`;
- `exit`: `code` и `reason` (`done`, `signal`, `error`).

## Отличия от Geneva

- Мутация (`ActionTree.mutate`) учитывает `--disable-action`. В Geneva
  отключённые действия могли вернуться через мутацию.
- `--no-reject-empty` работает как написано: по умолчанию пустые стратегии
  отбрасываются. В Geneva флаг был инвертирован.
- Смена типа tamper с `corrupt` на `replace` подбирает значение. Geneva
  писала `replace:None`.
- Значения, которые нельзя записать в стратегии (адреса IPv6 с `:`, строки
  с пробелами и разделителями), не выбираются. Каждая особь проверяется на
  то, что её текст разбирается обратно в ту же стратегию.
- В дереве не больше 64 действий. Мутация, которая 1000 раз подряд даёт
  отвергнутые стратегии, оставляет особь как есть (Geneva зацикливалась).
- Из Geneva сохранены: частоты действий, вероятности ветвей мутации,
  порядок «скрещивание, затем мутация», турнир из 10 особей, правила отказа
  по залу славы и выбор триггера из настоящих пакетов. Последовательность
  случайных чисел, конечно, другая.
